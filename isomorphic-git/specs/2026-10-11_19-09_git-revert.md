## Core goal / Done contract
正确撤销目标提交相对父提交的变更，在当前HEAD上生成一个新commit，其parent为操作前HEAD；保留目标提交之后无冲突的改动，不能reset整棵父树、不能提交已有staged数据。干净仓库、受支持类型和预算内才执行。冲突与不支持必须在真实worktree/index/refs写前拒绝；阶段B写失败报告partial并保留事务恢复证据，不声称跨文件crash-atomic。
阶段A（先批准）仅read-only inverse plan/dryRun及短验证，阶段B真实apply/commit在A证据后再次checkpoint批准，A结束不称revert可执行完成。

## Confirmed implementation facts
- commands.ts gitRevert目前REVERT_NOT_SAFE，旧实现是错误parent-tree reset。
- vendor1.38.1内部mergeTree支持给定our/base/their树与dryRun，非现成公共revert API。
- 正确三方反向合并：base=target commit tree，ours=current HEAD tree，theirs=target唯一父commit tree。不是merge-base祖先自动计算，也不是base=target父。
- 内部mergeTree abortOnConflict=true不应写worktree/index；冲突可作为返回Error对象而非throw，调用层必须显式识别，不能将对象当OID。
- mergeBlobs将bytes转UTF8且注释只有100644/100755，但blob还可能120000、binary，不能直接泛用；typed/mode/UTF8/二进制预检或自定义mergeDriver必须保护。internal dryRun是否全过程零物理写尚未运行验证，不能只凭参数名承诺。
- 生产唯一vendor扩展链/可复现构建已有stageBatch；可新增轻量read-only extension复用已有mergeFile算法，不引进第二Git业务实现。所有测试走生产loader/adapter；不新建subagent，不恢复长job。
- 当前snapshot-store只保护add index及map，不能代表revert多文件+index+branch ref事务可恢复。不能把index恢复当整个revert回滚。

## Phase A checkpoint: readonly inverse planning
### Contract
- `command:revert,ref,dryRun:true` -> targetOid,parentOid,headOid,changed paths/action/mode,size,冲突列表、预算/unsupported拒绝和是否可执行计划（apply仍未上线）。普通revert暂仍REVERT_NOT_SAFE或REVERT_APPLY_NOT_READY。
- 正常symbolic branch HEAD；detached拒绝。目标必须是当前HEAD可达ancestor且仅一个parent；root与merge提交显式REVERT_UNSUPPORTED，不暗设mainline。ref验证成commit，目标重复revert/逆结果没有改动返回REVERT_EMPTY。
- worktree/index必须干净（含untracked新文件，ignored按明确模式不算脏）；已有MERGE_HEAD等未结束事务/冲突index/snapshot pending拒绝。dryRun绝不自动stash或建map。
- 安全只读遍历commit trees，恢复路径不接受绝对/../NUL；拒绝gitlink/submodule、不支持类型与file-directory冲突。树entries/changed files/总bytes/单blob明确定额（复用add预算参数，默认5000 files/20000entries/32MiB单blob/256MiB总体；硬读取snapshot16MiB等B另协调）。deadline/合作yield每pass，path-parent预检。
- 三方对象相同直接选旧/当前对象；双方真正修改同一regular text blob时，严格UTF8 roundtrip+NUL检查后复用diff3计算逆merge，同文件不重叠行变更应保留；冲突返回路径，不给冲突标记写worktree。涉及binary/symlink/mode冲突只在对象三方trivial情况下支持，不trivial显式冲突，不强行UTF8合并。
- 新增read-only vendor扩展必须捕获/限制生成objects在in-memory overlay，或者仅导出纯mergeFile helper并在commands planner只读merge输入。优先纯helper+公开readTree/readBlob/writeTree的readonly计划（phaseA不调用writeTree）。同一可读registry源码重建归档与hash，保留license，不修改opaque bundle字符串冒充源。
- dryRun stats与path列表无文件bytes输出；预算/冲突结果只读。计划不跨命令缓存，不凭A完成的计划去B写；B必须重算/recheck。

### Single implementation and semantics
- scripts/git.ts现在纯Script.queryParameters→dispatchGit→Script.exit包装，git-dispatcher.ts唯一共享dispatcher可注入仅repo-map root做完整临时E2E；不是第二业务实现。原静态模块/性能测试改读真实dispatcher，而shorthash链扩展包括它与revert模块。
- planner以内部一次性materialize回调提供candidate entries/new mergedblob bytes，不出JSON；base target/ours HEAD/theirs parent逆merge，后续修改保留，freshsource检查。
- executeRevert构造candidate objects（可失败遗留unreachable blobs/tree/commit），候选index内存overlay仅读写gitdir/index到buffer。git.writeCommit直接指定candidate tree及parent originalHEAD，绝不git.commit真实旧index。newcommit message含This reverts commit，显式author校验。
- old备份＋newbytes读回＋intent binding核验，写前再次oldcurrent摘要一致。受影响worktree regular file写/删除核验，index物理write一次，branch ref最后write；最终inventory、statusMatrix refresh:false clean、fsassertHealthy后写done读回，inspect核验closure解除pending。
- B1 op apply带transactionId+fresh currentDigest，锁内重算planner并与manifest head/target/changes比对；不可reuse已有candidate attempt（先cancel/recover）。正常ref revert自动完整prepare/apply不需手动prepare。
- op recover要求一个pending、原backupValid+prepared、有startedintent（partialintent亦可）、fresh currentDigest。先独立attempt保存freshcurrent各bytes/absence并核验capture，写前重查current摘要；restore旧worktree/index/HEAD/packedref，branchref-last，库存回读后resolved闭合。明确会恢复全部记录旧状态，可能撤销期间recordedpath新变化，但新内容先被保存；无自动rollback，不跟随symlink、不清untracked或空dirs。
- recover本身失败留attempt/pending，freshinspect/hash后可重试；old/new/recovery失败attempt磁盘bytes累计cap96MiB/8attempt；每inventory32MiB，每file16MiB，history8事务且无自动cleanup。非法oldbackup/多pending/oversizeunsafecurrent仍拒绝，未支持强制修复原manifest损坏。closed历史old/new/current证据继续验证，后续正常targets变化不重开历史；不称marker历史永久保障如今target。
